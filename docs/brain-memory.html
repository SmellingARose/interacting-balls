Giving the chaser a memory

The ball brain decides every Δt = 40 ms. Right now it sees only the current sensor snapshot xt and outputs commands ut, so it forgets everything between decisions. Each option below adds memory in a different way. Purple marks the memory path in every picture.

Today · no memory

The baseline

ut = N(xt) // commands depend only on this instant

With ±10 m of sensor noise, each snapshot is wrong by several times the 2 m hit size, and nothing lets the brain average it out. The chart shows what it sees: grey dots are the readings, the dark line is the truth.

Option 1

Previous outputs as inputs

ut = N(xt, ut−1)

The network knows what it just did, so it can avoid flipping between full left and full right. It knows nothing more about the target than before.

Option 2

Previous inputs (frame stacking)

ut = N(xt, xt−1, xt−2) // averaging k readings: noise σ → σ/√k

Seeing several snapshots lets the network compute a rate, (xt − xt−1)/Δt, and average a little noise. Its memory only reaches back k steps, and every extra snapshot multiplies the inputs, so the network gets slower.

Averaging k snapshots of ±10 m noise: 4 snapshots halve it, but you need 25 to get under the 2 m hit size, and by then the oldest reading is a second out of date.

Option 3

Change since last decision

Δxt = xt − xt−1 ω ≈ Δθ / Δt // line-of-sight turn rate

Classic guidance steers to keep the line of sight from turning (ω → 0 means a collision course). Handing the network Δθ directly measures that turn rate. The catch: subtracting two noisy readings adds their noise, giving σ√2, so this works best on smoothed readings.

Option 4

Smoothed sensors (moving average)

x̂t = x̂t−1 + α · (zt − x̂t−1) // z = raw reading, 0 < α ≤ 1
noise → σ·√(α / (2−α)) lag ≈ (1−α)/α decisions

Each new reading only nudges the estimate. With α = 0.2, noise drops to a third, but the estimate trails a moving target by about 4 decisions (160 ms). That's the trade: less noise, more lag.

The trade-off for every α: lower α means less noise (blue) but more lag (orange). No setting gets both low, which is why plain smoothing struggles against a moving target.

Option 5

Tracking filter (α-β, the simple Kalman)

predict: p⁻ = p̂ + v̂·Δt
error: r = z − p⁻
correct: p̂ = p⁻ + α·r v̂ = v̂ + (β/Δt)·r
undo delay: pnow ≈ p̂ + v̂·d // d = sensor delay

The filter knows targets move smoothly, so it predicts where the runner should be and only partly trusts each reading. Keeping a velocity estimate removes the lag of plain smoothing, and projecting forward by v̂·d undoes the sensor delay. A Kalman filter is the same loop with α and β calculated from the noise levels: gain K = P/(P+R), where P is how unsure the prediction is and R how noisy the sensor is.

Option 6

Learned memory slots

[ut, mt] = N(xt, mt−1) // m = a few numbers the network writes for itself

The network decides what to remember: for example "runner swerved left last time" or "final approach now". Evolution has to discover useful uses for those slots, and that's slow, because a slot's value only pays off decisions later.

+4–8 inputs and outputsnetwork chooses what to keephard to evolve
Option 7

Memory neurons (recurrent network)

ht = tanh(W·xt + U·ht−1 + b) ut = tanh(V·ht)
extra weights: U is H×H // 32 neurons → +1,024 weights

How to read it: it's one network, drawn three times for three decisions in a row. Bottom to top, each decision goes: what it sees → its memory (the hidden neurons) → what it does. The purple arrows are the new part: each decision's memory is handed to the next one, scaled by the weights U. So memory h₂ is a mix of what it sees now (x₂) and what it remembered (h₁).

Every hidden neuron feeds its value into the next decision through the weights U, so memory is built into the network. It can learn filtering, timing and weave anticipation on its own. Because each weight now affects every later decision, random mutations rarely improve it, and large U values can make h explode or stick at ±1.
